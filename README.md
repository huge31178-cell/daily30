# 每日30条热点新闻 · v2（更重视新闻重要性 + 按日历史存档）

这是 **个人阅读索引**，不是新闻机构，也不是权威热搜榜。页面只展示标题、时间、媒体名称和链接，不复制新闻正文；来源的转载许可与商业使用请自行核对。

## 已升级的功能

- **三个独立 TOP10 栏目**：中国热点、全球热点、中国娱乐。
- **从约20条RSS/聚合订阅抓取候选**，按固定窗口筛选：前一天北京时间09:00至当天09:00。
- **同一事件近似标题合并**：同一媒体多个栏目转载不按多个独立媒体计算。
- **综合排序**：事件潜在影响力 + 不同新闻机构报道数（重要） + 订阅源质量权重 + 少量发布时间与版面位置分数；普通招聘/展览等降权。
- **来源透明**：显示新闻原链接、媒体和发布时间；多媒体相似事件标注“X家媒体涉及”，**并不代表事实已经交叉核实**。
- **真实缺失处理**：源站失联或某栏目不足10条时，不编造/补超时新闻。
- **历史日报**：自动把每天的固定日报保存为 `history/YYYY-MM-DD.json`，页面可以点击「最新一期」「昨天」或下拉选择历史日期。
- **导出长图**：导出的是当前打开的日期，而不是始终导出最新一天。

## 截稿日期说明（容易误解，务必看）

- 每天北京时间 **09:00** 视为一天的固定截稿时间。例如 `2026-11-12` 这期：统计 `2026-11-11 09:00` 至 `2026-11-12 09:00`。
- 定时任务设为北京时间 **09:20 尝试运行**，给RSS更新留出时间。GitHub Actions可能延迟或偶尔不触发，无法保证严格09:20发布。
- 程序若在08:30手动运行，会生成的是**上一期已完整截稿**的日期，不会把尚未完成的今天算入。
- 第一次成功写入历史后，此后每天继续积累。**过去未保存的日报无法自动、完整地复原**；不要用今天的数据冒充昨天。
- 同一天重复运行默认复用同一个历史文件，避免榜单反复变化。如果需要强制重抓可在工作流环境中设置 `FORCE_REFRESH=1`（不推荐普通用户使用）。

## 如何升级已经运行的仓库（你的仓库为 `huge31178-cell/daily30`）

### 用浏览器上传替换（沿用你之前熟悉的步骤）

1. 下载 `daily30_v2_upgrade.zip` 并解压；不要直接上传zip。
2. 到 [仓库首页](https://github.com/huge31178-cell/daily30) → `Add file` → `Upload files`。
3. **进入解压后的文件夹内部**，将以下内容拖入上传区域（包括两个文件夹；路径必须保留）：
   - 根目录：`index.html`、`app.js`、`style.css`、`update_news.py`、`README.md`。
   - 隐藏文件夹：`.github/workflows/deploy.yml`（覆盖现有工作流）。
   - 新文件夹：`history/index.json`（新增日期索引初始化文件）。
4. 如果 GitHub 页面不允许直接覆盖同名文件，请分别打开仓库里的文件 → 点编辑铅笔 → 全选替换为新文件内容；工作流文件也必须更新。更省事的替代方案是通过 GitHub Desktop 将解压文件复制到克隆仓库并提交推送。
5. 点击「Commit changes（提交更改）」后，进入 `Actions → 每日新闻更新与网站发布`，手动 `Run workflow`。
6. 确认绿色对勾，再打开 [你的新闻网站](https://huge31178-cell.github.io/daily30/)；网页会出现「昨天」「历史日期」。

**非常重要**：不要把整个 `daily30_v2_upgrade` 文件夹当作子文件夹上传。仓库根目录仍然应直接看到 `index.html`。不要删除已经存在的 `data.json` 或 `history/YYYY-MM-DD.json` 文件。

### 通过 GitHub Desktop（如浏览器无法覆盖同名文件）

1. [安装 GitHub Desktop](https://desktop.github.com/) → 登录 → File → Clone repository → `huge31178-cell/daily30`。
2. 打开本地仓库文件夹，解压 `daily30_v2_upgrade.zip`，将压缩包内部内容复制覆盖至仓库根目录（保留 `.github` 目录结构）。
3. 在 GitHub Desktop 输入提交说明 `Upgrade news ranking and history` → Commit → Push origin。
4. 进入 Actions 检查自动运行。

## 自动归档和 GitHub 权限

工作流设置 `contents: write`，成功生成后会自动 `git add data.json history/`，提交并推送每日 JSON 快照，然后再部署 Pages。若报错 `403 Resource not accessible by integration`，需要检查仓库 Actions 的 Workflow permissions 是否允许读写仓库（不同账号/组织配置可能有差异）。

## 排名局限

本项目能比旧版更好地去重和压低边缘新闻，但依然**不是全球新闻热度数据库**。RSS覆盖不完整；多个媒体对同一事件的标题不一定能聚成一组；上游发布时间可能延迟；部分媒体只在原站发布不提供RSS。Google News 搜索/栏目RSS为非官方稳定API，可能改变、失效或受使用条款限制；不可据此保证「真正全球最重要的前10条」。如果用于公开/商业发行，请先核实每个新闻源的使用许可。
